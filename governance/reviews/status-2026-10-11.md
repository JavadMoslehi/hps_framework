## Namespace, lookup and ownership contract

Common success is zero. Negative error constants use disjoint 65,536-code
partitions: module 0 framework (-1..-65535), 1 memory (-65537..-131071) and 2 bytes
(-131073..-196607). Reason zero is reserved; future IDs 3..65534 need static
registration, with UINT16_MAX reserved for UNKNOWN. Published IDs/reasons cannot
be reassigned. Existing HPS_POOL/HPS_BYTE names remain, now aliases/constants of
the common signed type. Framework defines four errors, memory seven and bytes four.

hps_status_module classifies owned ranges, including unregistered reasons;
success maps to framework. Gaps, positive values and unallocated ranges map to
UNKNOWN. Direct signed comparisons perform no arithmetic, negation, shifts,
narrowing or indexing on arbitrary input, including INT64_MIN/INT64_MAX.
hps_status_string switches over sixteen distinct registered values including
success. It returns a borrowed immutable program-lifetime NUL-terminated string
in the execution character set: "ok", a module-qualified description, or
"unknown status". Maximum storage contract is 32 C bytes including NUL. Message
text is diagnostic, not a stable protocol or localization identifier.

No output buffer, heap/OS service, mutable registry, initialization, runtime
registration, callbacks, retry or synchronization is added. Lookup does not call
pool/bytes functions or change their state. Module headers provide only constants
and types for the registry. The link graph is memory/bytes -> status -> base;
there is no runtime module dependency or link cycle from status back to modules.
Existing pool ownership, no-erase and single-context restrictions remain intact.

## Migration, resources and policy mapping

Module status aliases change from uint8_t/positive errors to int64_t/negative
errors. Keep named comparisons; update persisted numeric assumptions, foreign
interfaces, status storage and callback/return ABI. Rebuild all libraries and
consumers together. No automatic truncation or numeric old-code translation is
provided. Public pool-stats/view/buffer/reader layouts contain no status fields
and are unchanged. The pool's private last_status and automatic status objects
widen; stack/RAM/return-register/helper impacts need target review.

Sixteen registered codes and seventeen source diagnostic literals (including
fallback) are fixed. Source literal storage totals 351 C bytes including NULs,
with the longest occupying 28; compiler placement/merging and final ROM/code size
are unmeasured. Lookup work is bounded by three owned ranges and sixteen switch
cases; generated latency/stack and WCET are unverified. Link HPS::status or
hps-status; memory/bytes inherit the dependency. Make builds the same source in
the shared executable. test_status is fifth in the runner and has no module main.
