## Design and mapped requirements

- HPS-C-001/004/013, HPS-HDR-001 through 005: uint8_t bytes/status/flags, size_t
  lengths; namespaced prototypes, private helpers, guarded independent headers and
  guarded C linkage. No global mutable state, compiler attributes or new macros
  changing runtime behavior. C/C++ include/link evidence under HDR-006 is pending.
- HPS-C-006/007/008/009/011/012: length <= capacity checked before subtraction;
  append source <= capacity-length before addition or destination pointer formation;
  slice offset <= length before subtraction and count <= remaining before pointer
  formation. Nonempty slices necessarily have offset < length. Empty paths never
  index/add to NULL or call memmove. At requires index < length. Equality checks
  both descriptors and equal lengths before dereference, and increments only while
  index < length. All failures are detected before mutation and preserve outputs.
  Actual array extents, initialized source bytes and live pointers are caller proof
  obligations. Source inspection does not close MISRA essential-type/pointer rules.
- HPS-C-010/014, HPS-MEM-001/002/005, HPS-EXEC-001 through 003: no unrelated casts,
  address integer conversion, heap/pool calls, VLA, recursion, callback, retry,
  locking or module scratch array. Constant-work descriptor operations; linear
  comparison/copy with input extent bounds. memmove supplies overlap semantics and
  is an explicit target dependency; compiler/libc helpers and transitive no-heap,
  stack/WCET require actual target evidence. No universally fastest claim.
- HPS-SEC-001/002/003/005/006: binary data has no text/NUL assumptions; callers
  validate external lengths against actual storage before constructing views.
  Capacity exhaustion fails without partial modification. Clear/truncate retain
  bytes; equality exits early, so neither secret erasure nor constant-time security
  is promised. Ownership/lifetime/context are documented rather than inferred.
- HPS-VER-001 through 004, HPS-REL-001/003: new source, headers, contract and prepared
  tests; additive API, no changes to pool/base ABI. CMake/Make/Meson register the
  library/test for later execution, without running a configure/build. Header
  portability discovery includes the new headers automatically. Policy core
  concurrency/I/O checks now cover src/bytes as well as src/memory.

## Threat model and residual assumptions

Assets: backing bytes, active length/capacity integrity and bounded work.
Entry points: view and buffer functions. Trust boundary: incoming pointer/length
pairs and descriptors are caller-owned; a pointer alone does not prove an extent.
Malformed NULL/length/state combinations and out-of-bounds requests fail before
access, but forged non-NULL addresses, false extents, indeterminate objects and
use-after-lifetime remain outside the module's protection. Backing/output metadata
must be disjoint; payload overlap is supported by memmove. Caller serialization,
finite admission limits and storage ownership are required. Mutable aliases can
change bytes observed by views; the module provides no lifetime tokens or locks.

Industrial release remains blocked: all 221 MISRA rows are unresolved, no qualified
production target/deployment profile, independent reviewer, memmove dependency
qualification, sanitizers, analyzer, stack/timing or mixed-language ABI evidence.
Rows with this review as evidence are still unassessed, not closed by source checks.

## Prepared verification

Tests cover view ranges and equality, embedded zero/high bytes, canonical empties,
NULL and malformed metadata, SIZE_MAX bounds, metadata/payload/output preservation,
full/zero-capacity buffers, truncation without erasure and self-descriptor slicing.
An independent 16-byte snapshot model defines expected copying for 2,025 append and
2,025 assign cases, including forward/backward overlap, equal starts and disjoint
ranges. No operation is hidden in assert expressions. These are test intentions;
no C test success is claimed. Policy checker self-tests and whitespace checks pass.
